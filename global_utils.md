## Global_Utils

**A collection of reusable SAS utilities for clinical programming.**

GlobalUtils is an open-source SAS package containing reusable
macros designed to simplify clinical data programming,
CDISC dataset development, data validation, specification
processing, and workflow automation.

The package is developed and maintained as part of the
global_utils GitHub repository, which also includes
independent Python and R utilities.

### Main Features

- Reusable SAS macros for clinical programming.
- Utilities supporting CDISC SDTM and ADaM development.
- Data processing and validation utilities.
- Workflow automation and productivity tools.
- Modular macros that can be used independently.

### Usage

Install and load GlobalUtils using the SAS Packages Framework.

For documentation and source code, visit:
https://github.com/manivannan-mathiazhagan/global_utils

## `%build_cdisc()` macro <a name="buildcdisc-macro-1"></a> ######

### Macro:
    %build_cdisc

### Purpose:
    Builds final SDTM or ADaM datasets from a programmed intermediate
    SAS dataset using synchronized CDISC specification metadata.

    The macro applies specification-defined variable order, labels,
    sorting, and SDTM sequence numbering. For SDTM, it also creates
    the corresponding SUPPxx dataset when supplemental qualifiers
    are defined and contain nonmissing values.

### Parameters:

 - `dev` (required)
      Specifies the CDISC dataset type.

      Valid values:
      - SDTM
      - ADAM

      The macro uses this value to determine the output library
      and corresponding specification metadata.

 - `inds` (required)
      Input intermediate SAS dataset containing the programmed
      variables.

      Example: `WORK.DM_FINAL`

      The dataset must exist before executing the macro.

 - `dsn` (required)
      Name of the final CDISC dataset to create.

      Examples:
      - DM
      - AE
      - ADSL
      - ADAE

      The dataset name must be defined in the corresponding
      specification metadata.

 - `debug` (optional)
      Controls whether temporary BUILD_CDISC datasets are retained.

      Valid values:
      - Y: Retain temporary WORK._BC_* datasets.
      - N: Delete temporary WORK._BC_* datasets.

      Default: N

### Input Datasets:

    Programmed intermediate dataset:
    - Dataset specified by `inds`

    SDTM specification metadata:
    - SPEC.SDTM_DATASETS
    - SPEC.SDTM_VARIABLES
    - SPEC.SDTM_SUPPVARIABLES

    ADaM specification metadata:
    - SPEC.ADAM_DATASETS
    - SPEC.ADAM_VARIABLES

### Output Datasets:

    SDTM:
    - SDTM.<dsn>
    - SDTM.SUPP<dsn>, when applicable

    ADaM:
    - ADAM.<dsn>

    Temporary datasets:
    - WORK._BC_VARS
    - WORK._BC_MAIN
    - WORK._BC_SUPP
    - WORK._BC_ONE_SUPP

    Temporary datasets are retained only when DEBUG=Y.

### How it works:

 1. Validates the required parameters and input dataset.

 2. Determines the output library and metadata datasets
    based on DEV=SDTM or DEV=ADAM.

 3. Retrieves dataset sorting information from the
    specification dataset metadata.

 4. Retrieves variable metadata in specification order.

 5. Identifies variables defined in the specification
    but missing from the programmed intermediate dataset
    and writes a warning to the SAS log.

 6. Sorts the intermediate dataset using the
    specification-defined key variables.

 7. For SDTM datasets, generates the --SEQ variable
    when defined in the specification.

    Sequence numbering is performed within STUDYID
    and/or USUBJID when those variables are available.

 8. Applies variable labels and retains variables
    in the specification-defined order.

 9. Creates the final dataset in the SDTM or ADAM
    output library.

10. Applies the final specification-defined sort order.

11. For SDTM, creates SUPPxx from supplemental
    specification metadata when applicable.

12. Deletes temporary WORK datasets unless DEBUG=Y.

### Sample code:

#### Example 1: Build an SDTM DM dataset

~~~sas
%build_cdisc(
    dev=SDTM,
    inds=WORK.DM_FINAL,
    dsn=DM
);
~~~

#### Example 2: Build an SDTM AE dataset

~~~sas
%build_cdisc(
    dev=SDTM,
    inds=WORK.AE_FINAL,
    dsn=AE,
    debug=N
);
~~~

#### Example 3: Build an ADaM ADSL dataset

~~~sas
%build_cdisc(
    dev=ADAM,
    inds=WORK.ADSL_FINAL,
    dsn=ADSL
);
~~~

#### Example 4: Retain intermediate datasets for debugging

~~~sas
%build_cdisc(
    dev=SDTM,
    inds=WORK.LB_FINAL,
    dsn=LB,
    debug=Y
);
~~~

### Prerequisites:

 - The SPEC library must be assigned.

 - The SDTM or ADAM output library must be assigned.

 - Specification metadata must be synchronized before
   executing the macro.

 - The input intermediate dataset must exist.

 - The target dataset must have corresponding variable
   metadata in the specification.

 - For SDTM supplemental qualifiers, source variables
   must use an underscore prefix in the intermediate
   dataset.

### Notes:

 - The macro supports both SDTM and ADaM datasets.

 - Existing target datasets are deleted before the
   replacement dataset is created.

 - Only variables defined in the specification
   are retained in the final dataset.

 - Missing input variables defined in the specification
   generate warnings in the SAS log.

 - SDTM --SEQ numbering is generated when a sequence
   variable is defined in the specification.

 - Supplemental qualifier datasets are created only
   when applicable and nonmissing supplemental
   values are available.

 - The macro does not perform general CDISC compliance
   validation.

 - DEBUG=Y retains temporary datasets to support
   troubleshooting and review.

## `%isodtc()` macro <a name="isodtc-macro-2"></a> ######

### Macro:
    %isodtc

### Purpose:
    Derives a character date/time variable in ISO 8601-style format
    from numeric SAS datetime, numeric SAS date, character date,
    numeric time, and/or character time variables.

    Supports partial character dates and provides options to control
    the inclusion of zero time values and seconds.

    This macro is intended to be called inside a DATA step.

### Parameters:

 - `datetimen` (optional)
      Name of the input numeric SAS datetime variable.

      The date and time components are extracted from the
      supplied datetime value.

      Example: AESTDTM

      Default: (blank)

 - `daten` (optional)
      Name of the input numeric SAS date variable.

      The numeric date is converted to YYYY-MM-DD format.

      Example: AESTDT

      Default: (blank)

 - `datec` (optional)
      Name of the input character date variable.

      The macro extracts the year, month, and day from
      space-separated date components.

      Supported month representations include abbreviated
      month names and numeric month values.

      The macro also handles missing or unknown date components.

      Example: AESTDAT

      Default: (blank)

 - `timen` (optional)
      Name of the input numeric time-related variable.

      The macro uses TIMEPART() to derive the time component.

      Example: AESTTIM

      Default: (blank)

 - `timec` (optional)
      Name of the input character time variable.

      The value is interpreted using the SAS TIME informat
      and converted into a character time component.

      Example: AESTTIMC

      Default: (blank)

 - `outdtc` (required)
      Name of the output character date/time variable.

      The macro creates this variable with a length of $19.

      Example: AESTDTC

      Default: (blank)

 - `rmzertim` (optional)
      Controls whether zero time values are removed.

      Valid values:
      - Y: Remove zero time values where supported.
      - N: Retain zero time values.

      Default: N

 - `rmzersec` (optional)
      Controls the removal of zero seconds from time values.

      Valid values:
      - Y: Use time without seconds where supported.
      - N: Do not explicitly remove zero seconds.

      Default: Y

 - `nosecond` (optional)
      Controls whether seconds are included in the
      selected time format.

      Valid values:
      - Y: Use HH:MM format.
      - N: Use HH:MM:SS format where supported.

      Default: Y

 - `debug` (optional)
      Controls whether intermediate variables are retained.

      Valid values:
      - Y: Retain intermediate variables.
      - N: Drop intermediate variables.

      Default: N

### Input Variables:

    At least one of the following inputs must be specified:
    - DATETIMEN
    - DATEN
    - DATEC
    - TIMEN
    - TIMEC

    The input variables must exist in the current DATA step.

### Output Variables:

    The macro creates the character variable specified
    by OUTDTC.

    Output length: $19

    Depending on the available date and time components,
    the output may contain:

    - YYYY-MM-DD
    - YYYY-MM-DDTHH:MM
    - YYYY-MM-DDTHH:MM:SS
    - YYYY-MM
    - YYYY

    The macro also contains logic for constructing
    partial date/time values.

### How it works:

 1. Determines the time format based on NOSECOND.

 2. Extracts date and time components from DATETIMEN,
    when supplied.

 3. Converts DATEN to an ISO-style date using the
    SAS IS8601DA format.

 4. Parses DATEC into year, month, and day components.

 5. Converts supported abbreviated and numeric month
    representations into two-digit month values.

 6. Applies the RMZERTIM, RMZERSEC, and NOSECOND
    options to the time components.

 7. Converts character time values using the SAS
    TIME informat.

 8. Selects the final date component in this order:
    - DATETIMEN
    - DATEN
    - DATEC

 9. Selects the final time component in this order:
    - DATETIMEN
    - TIMEN
    - TIMEC

10. Combines the available date and time components
    into the output character variable.

11. Writes warning messages for certain invalid
    year or month values from DATEC.

12. Drops intermediate variables when DEBUG=N.

### Sample code:

#### Example 1: Numeric SAS date to ISO date

~~~sas
data want;
    set have;

    %isodtc(
        daten=VISITDT,
        outdtc=VISITDTC
    );
run;
~~~

#### Example 2: Numeric SAS datetime to ISO datetime

~~~sas
data want;
    set have;

    %isodtc(
        datetimen=AESTDTM,
        outdtc=AESTDTC,
        nosecond=N,
        rmzersec=N
    );
run;
~~~

#### Example 3: Character date to ISO-style date

~~~sas
data want;
    set have;

    %isodtc(
        datec=AESTDAT,
        outdtc=AESTDTC
    );
run;
~~~

#### Example 4: Separate numeric date and character time

~~~sas
data want;
    set have;

    %isodtc(
        daten=AESTDT,
        timec=AESTTIMC,
        outdtc=AESTDTC
    );
run;
~~~

#### Example 5: Remove zero time and zero seconds

~~~sas
data want;
    set have;

    %isodtc(
        datetimen=AESTDTM,
        outdtc=AESTDTC,
        rmzertim=Y,
        rmzersec=Y
    );
run;
~~~

#### Example 6: Retain intermediate variables

~~~sas
data want;
    set have;

    %isodtc(
        daten=VISITDT,
        outdtc=VISITDTC,
        debug=Y
    );
run;
~~~

### Prerequisites:

 - The macro must be called inside a DATA step.

 - Input variables must be available in the current
   DATA step.

 - Numeric date and datetime inputs must use
   appropriate SAS date/datetime values.

 - Character date inputs are expected to contain
   space-separated date components.

 - The macro references the UWARN macro variable
   when reporting certain invalid date components.

### Notes:

 - The macro does not create a separate dataset.

 - The output variable is character with length $19.

 - Date and time input parameters are optional,
   but OUTDTC and at least one input are needed
   to derive an output.

 - If multiple date inputs are supplied, DATETIMEN
   takes precedence over DATEN and DATEC.

 - If multiple time inputs are supplied, DATETIMEN
   takes precedence over TIMEN and TIMEC.

 - NOSECOND, RMZERSEC, and RMZERTIM interact;
   their effects depend on the selected input path.

 - Character dates with unknown components may
   produce partial dates.

 - DEBUG=Y retains intermediate variables whose
   names are prefixed with double underscores.

 - The macro does not perform comprehensive ISO 8601
   validation of all possible input combinations.
